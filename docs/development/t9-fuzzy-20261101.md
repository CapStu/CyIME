# 九键按读音查近音词

中文全拼和双拼九键沿用「模糊音」里的分组。按数字先给原来的候选。点左栏的读音才查近音词，带 ≈ 的读音允许用原来的数字长度选择另一种发音。双拼显示拼音，实际选择使用当前方案的双拼编码；例如小鹤的 `shi` 送入引擎的是 `ui`。

九键的拼写补丁把模糊读音放在数字映射之后。最初试过在数字映射之前派生，数字输入也会遍历所有近音。固定聊天语料的空词库和预置词库各有 12 处目标名次退步，逐键工作量超限，未采用。设置关闭时删除应用自己写的拼写补丁，用户的其他配置保留。

用设置层实际生成的全拼、小鹤九键方案和两组启用的读音（s/sh、in/ing）部署本地引擎，记录在 `D:/CyIME-Data/eval/t9-fuzzy-20261101/final.log`。两种九键输入 `7454` 再选 `si` 都得到“司机”第一、“实际”第四，分别可完整上屏。全拼输入 `946` 选 `xin` 时“星”第五。全拼输入 `7454` 先选单字“是”，仅消耗前两键，保留 `54`。普通输入的对照与逐键耗时使用固定回放另行检查。

固定回放复用同一份已归档的本地 JNI 引擎与资源，通过 `--schema-patch-file` 把设置页生成的九键补丁部署到隔离词库。四个交替样本 BCBB，键间隔均为 0 ms。原聊天语料 130 段，空词库和含 3,000 条词频的词库各 4,370 个时点：候选列表、首选和目标名次均未变，逐键工作量门禁通过。连续输入的基线／启用均值分别为 3.8093／3.8489 ms、5.9112／4.6516 ms，停顿输入为 4.3920／3.6425 ms、5.9783／4.8312 ms，均无计时警告。比较报告是实验目录的 `complete-empty/comparison.json` 和 `final-seeded/comparison.json`。这是电脑同源引擎比较，并非设备测速。

专项测试 14 项通过，覆盖开关、全拼／小鹤／自然码各组双向读音、左栏触摸与纯文本粘贴。最终 Gradle 单测共享输出目录不可读，改用项目的 Kotlin 编译器和测试类路径独立编译运行，日志为 `ui-verified.log`。仓库内的 `NineKeyFuzzyProbe` 另核对了 11 次实际选词及剩余数字，见 `contract.log`。开启全部组后，左栏索引在本机 9,115 次查找的 p95 为全拼 1.9 微秒、小鹤 1.0 微秒，未测手机耗时。已查看 `nine-fuzzy-rail.png`、`nine-fuzzy-settings.png`，未打包、未安装，真机未验收。
