# 九键单按 3 出「的」、「就」后打「觉得」（2026-11-05）

群友反馈（截图 1000631431.jpg）：单按 `3` 首选「额 / 嗯 / 饿」；在「纯机体差异，精防肩撞就」后打 `58333`，首选「觉的」，「觉得」排第二。

## 原因

用云端同源引擎（1.15.58 main c189ffe、公开词组模型 t9_ngram-v3-ls-tri-c3、万象 LTS 语法 e34500ab、空个人词库）复现，结果和截图逐项一致，与旧版词库或个人学习无关。装了 CyLM 的设备会把这两处排对，所以不是每个人都能看到。

- **单按 3**：10-03 的修复把单键的额外简拼扣分乘 0.75。换成词组模型后，第一个词按「句首概率」或「上文后的概率」打分：句首 ln P(额) = -7.34，ln P(的) = -6.26，「的」再扣 3.75，排到了「额」后面；在「就」后面，「饿」得 -8.78，「的」得 -7.97 - 3.75。`single_key_recall_20261003` 的检查器在修前的当前代码上已经报 12 处失败。
- **觉的**：语料常把「觉得」写成「觉的」。ln P(的 | 觉) = -2.00，ln P(的 | 就 觉) = -0.66；而「就觉得」在模型里是一个整词，「就」后面接「觉得」只有 -10.37。合起来，「就 觉 的」-16.20 胜过「就 觉得」-16.54。「你」「都」后面同样如此。

## 改动

- `t9/single_key_initial_margin: 3.0`（`cyime_rime/t9_joint_decoder.cc`）：只按了一个 2–9 键、组句首选是完整韵母字（额、啊、哦）时，如果候选里有这个键作声母开头的字，并且它的总体词频（ln_ml）比完整韵母字高 3.0 以上（常用 20 倍），就把它排第一，完整韵母字作为第二条整句接在后面。只有 3 的「的」够格；6 的「你」（比「哦」高 1.88）、2 的「不」（比「啊」低）都不到，所以 2→啊、6→哦 不变。两个及以上的键不受影响。
- `t9/ngram_typo_bigrams: ["觉 的"]`：表里的两个词相连时，当作没见过的搭配计分，只用后一个词自己的低阶概率。组句里逐词打分和拆字链（`T9NgramModel::Chain` 新增可选参数）都用这条规则。
- 含这种搭配的词条（比如学过的「觉的」），上屏不到 3 次时不加词库先验，也不加用户学习层。被迫选过一两次的「觉的」不会再靠学习记录压过「觉得」；同一个人选够 3 次才按他的习惯排。
- 回放工具：夹具用例可以带 `left_context`，由 `ChatReplay` 交给引擎；不带这个字段的用例行为不变。新增 `fixtures/t9_rank_20261105.json` 和 `check_t9_rank_20261105.py`。

另外用 RankProbe 检查了预置词库：在 3,000 条种子词库上，「觉的」上屏 1 次时，「就」后首选回到「觉得」；上屏 3 次后按用户习惯排「觉的」；「觉得」学得比「觉的」多时首选「觉得」。

没修的同类问题（同属语料错字，不在这次单字修复范围内，已交给词组模型清洗）：「很 / 就 / 也 / 都」后面的「显的」会压过「显得」，「不晓的」也一样；「好 / 对」后面单按 2 首选「阿」（「好阿」）。
