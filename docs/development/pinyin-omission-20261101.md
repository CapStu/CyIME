# 26 键全拼漏一个字母的真机回归

## 装机结果

2026-11-01，SM-X800 覆盖安装私人测试包 1.15.27（20261379），APK SHA-256 为 440a8bb418fc9533f459d21399eaa639ca50c76ee477d4396207613a3b2f3b32。使用 Windows NDK 和 ADB。固定打包入口已通过 Release 构建和交付校验，手机仍是 1.15.25。

## 实现与范围

26 键中文全拼保留正常输入路径。连续输入停顿 180 毫秒后，在引擎线程复查会话与候选版本，对未分段确认、光标在末尾的字母串做补算。辅助拼音索引复用已有词表；每个音节尝试补一个字母，区分漏键后能否读成另一个完整音节。辅助索引是部署依赖，不是用户可选输入方案。

补算只在原首选和新结果不同的时候尝试，保留前两项，最多补两条覆盖整串编码的原生候选。过滤链刷新后复核前两项；不满足条件就恢复原菜单。点击补充项沿用正常引擎选词。排序器对已耗尽的反向迭代器先判界，避免分段选词时访问空列表。

## 配对回放

使用平板上安装的 APK、相同的内置资源和同一份键位邻接表，在独立用户目录通过 app_process 逐键回放。正常路径与停顿路径各跑 517 条。每条在同一次组合里检查停顿前后已有的前两项文字一致；两轮均完整通过。两次回放各自有分段选词历史，跨轮的个别排名变化不能归因给停顿补算。

表中“选不回”表示每一步在前 20 项里选能接上目标的最长前缀，仍不能完成整句。

| 分组 | 条数 | 整句前五，正常 → 停顿 | 选不回，正常 → 停顿 | 停顿补算中位 / P95 |
|---|---:|---:|---:|---:|
| 日常正确 | 120 | 116 → 117 | 0 → 0 | 2.4 / 5.2 ms |
| 日常漏键 | 120 | 23 → 60 | 96 → 59 | 3.4 / 11.7 ms |
| 独立短信正确 | 120 | 93 → 94 | 3 → 3 | 3.2 / 7.3 ms |
| 独立短信漏键 | 120 | 15 → 50 | 100 → 65 | 3.8 / 19.0 ms |
| 正常简拼 | 20 | 18 → 18 | 0 → 0 | 2.9 / 11.3 ms |

测得的补算耗时最高为 29.1 ms，不含 180 毫秒停顿时间。

只看「拼对时整句排第一」的例子，将同一轮 `idle.tsv` 中每条正确输入与它漏一个字母的输入逐条配对，按相同目标整句统计：

| 语料 | 拼对时排第一 | 漏一键后仍排第一 | 漏一键后进前五（含第一） | 漏一键后按前述分段策略仍选不回 |
|---|---:|---:|---:|---:|
| 日常短句 | 116 | 21 | 59 | 56 |
| 独立短信 | 94 | 15 | 50 | 42 |

单字控制项中，en/嗯、a/啊、o/哦、zhe/这、sha/啥、ne/呢、ba/吧、ma/吗、la/啦、ya/呀 都是首选。ai/哎 是第三，e/呃 是第七。这是指定的全拼路径；其他方案、已有个人学习记录可能给出不同结果。
