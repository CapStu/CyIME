# 评论和群聊打字回放 (2026-11-03)

问题：B 站评论、Q 群讨论这些真实句子，用 CyIME 能不能直接打出来。

## 做法

`tools/ime_lab/comment_typing_bench.py` 把每条消息切成分句 (两个标点之间的一段汉字)，分句整段一次打完算“整句”，
分句里 jieba 切出的词单独打算“词”。夹在数字或英文中间的分句 (26键、Pro版) 单列为“夹字母”，因为引擎看不到旁边打的数字。
含 8105 字表以外字 (繁体、生僻字) 的分句不测。拼音用 pypinyin，按手机习惯 ü 打 v；它读错的
长按、行尾、重试、怎么调 等在脚本里改正 (READINGS、调 读 tiao)。

每条用 `host_replay/RealTypingProbe.java` 的 type 模式在电脑同源引擎上逐键打 (不学习，每条从同一状态开始)：
看目标在前 100 个候选里的名次，以及按真人方式挑词要停几次。全拼带手机的邻键纠错表，小鹤双拼和九键不带。
新加 `PROBE_SCHEMA` 环境变量选方案；九键 (t9_pinyin) 按 ChatReplay 的做法在部署前写方案补丁、每键后 flush，
打完等停顿重排再看候选栏。

    python tools/ime_lab/comment_typing_bench.py cases OUT 评论.csv --charset <rime_ice>/cn_dicts/8105.dict.yaml
    python tools/ime_lab/comment_typing_bench.py userdir . USER t9_ngram.lm
    python tools/ime_lab/comment_typing_bench.py run OUT LIB USER CLASSES neighbors.txt full     # 每种方案一个新用户目录
    python tools/ime_lab/comment_typing_bench.py score OUT [--private]

`--private` 只写统计和词，不写原句，给不能离开电脑的群聊用。

环境：云端同源引擎 (1.15.51，ea6cd05)，九键词组模型完整版 v3-ls-tri-c3，没有九键语法文件 (已停用)。
小鹤双拼按待发的双拼整句补丁 (combo-words-1103) 测。

整句首选错时第二、三个候选几乎从不是整句 (前三只比首选高 0.5 点)，要停下来分段挑。

错句的原因：795 句全拼错句里 742 句是同音词选错 (词组模型挑的整句不对)，37 句首选读音和目标不同 (纠错或多音字)，
16 句首选不是整句。真正缺词的很少 (两字以上的词 0.3% 不在前 100)。

错得最多的 (全拼，句中)：的/得/地 混用 43 次，字母→字幕 16，在→再 15，打→大 15，键→见 12，它→他 11，显示→现实 11，
跨→夸 10，按→安 10，五笔→无比 9，智能→只能 7，视频→食品 6。
九键另有 豆包→豆瓣 26、方案→蛋糕 22、习惯→喜欢 20、打字→大一 15、双拼→双亲 15、开源→来源 9、语言→需要 9，
是九键同码词，词组模型的问题。

## 没做的

- 加大整句候选数 (translator/max_sentences 4→8)：+0.4 点，更慢；26 键开联合解码：-0.8 点。都不收。
- 的/得/地、在/再、它/他 这类单字选错是词组模型的问题，要改模型，不是补词。
- 九键整句 48.7% 远低于全拼，主要是同码词 (方案/蛋糕、习惯/喜欢)，同样要靠模型。
- Q 群聊天在电脑上跑 (原文不出电脑)，结果另记。
