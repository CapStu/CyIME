# 日语转换换成 azooKey（2026-11-02）

用户 11-02 看到对比结果后确认「可以换」。26 键和九宫格日语的假名汉字转换从 Rime + jaroomaji 词库换成 azooKey；
Rime 仍管输入串、分段、候选栏、部分选词、回车上屏和无痕。构建与来源见 `tools/azookey/README.md`。

## 对比（同一套输入，学习关闭）

测试集：97 句日常句（自编）+ AJIMEE-Bench 200 句（azooKey 团队，维基百科错字语料）。按标点切块，训令式罗马字（ん 用 nn，促音双写辅音），
逐键输入后取首选；整句与答案在 NFKC 归一后完全一致算对，另计字错率。时间是电脑上同一台机器的逐键耗时。

| 引擎 | 日常 整句全对 | 日常 字错率 | 日常 每键 | AJIMEE 整句全对 | AJIMEE 字错率 | AJIMEE 每键 |
|---|---|---|---|---|---|---|
| 旧：Rime + jaroomaji | 28.9% | 28.9% | 13.33 ms | 18.5% | 23.3% | 11.49 ms |
| azooKey 直接调用 | 85.6% | 2.1% | 3.53 ms | 42.0% | 8.3% | 3.71 ms |
| azooKey 经 Rime 翻译器（本次接入） | 85.6% | 2.1% | 6.78 ms | 41.5% | 8.4% | 6.59 ms |

接入版另加了助词按读音（wa/e/o → は/へ/を）；加之前 AJIMEE 为 42.5%，差 1 句（選手権→選手県）。
最慢一键 P95：旧 60.9 / 59.9 ms，新 61.2 / 82.7 ms（AJIMEE 长句）。Zenzai 神经模型未测（模型只在 Hugging Face，环境访问不到）。

## 2026-11-03 补回 Mozc 名词（暁山 打不出来）

用户反馈 1.15.47 打不出 暁山（あきやま）。原因：azooKey 词典没有这个词，原来的 jaroomaji 词库（来自 Mozc 开源词典）有。
做法：把 Mozc 开源词典（google/mozc 00724c6d）里 azooKey 没有的名词并进 azooKey 词典的 `louds/`（`tools/azookey/build-dictionary.sh`、`mozc-words.py`），
共 398,633 条：人名 15 万、地名 8.8 万、普通名词 6 万、サ変名词 4.6 万、机构名 3.4 万等；不收动词、形容词和纯假名词。引擎库不改。

| 电脑回放（学习关） | 日常 97 句整句全对 / 字错率 / 每键 | AJIMEE 200 句整句全对 / 字错率 / 每键 |
|---|---|---|
| 原 azooKey 词典 | 85.6% / 2.1% / 3.00–3.11 ms | 41.5% / 8.4% / 3.02–3.09 ms |
| 并入 Mozc 名词 | 85.6% / 2.1% / 3.21–3.22 ms | 43.5% / 7.5% / 3.25 ms |

P95 单键在误差内（20.5–23.3 ms）。另试过把补充词挂在 azooKey 的用户词典槽：结果相同但每键多 0.6 ms，未采用。
`akiyama` 候选：秋山、暁山、空山、秋山氏…（原来没有 暁山）。APK 内 `azookey/dictionary.zip` 从 11.3 MB 增到 19.2 MB，手机解压后从 25 MB 增到 44 MB。
`build-dictionary.sh` 从头（重新克隆、打补丁、编译）重跑，得到同一个 zip 哈希。构建脚本合并后的内容哈希与手机端校验一致（JVM 测试）。未真机验收。

## 2026-11-03 长音键 ー（コーヒー 打不出来）

用户反馈日语没有长音键、打不出 コーヒー。引擎本身没问题：电脑上经 Rime 插件输入 `ko-hi-`、`kolhil` 首选都是 コーヒー，L 键一直就是长音。
真正的问题是显示：拼写显示把 l 当成待拼的辅音（`pendingRomajiTail`），ko+L 显示成「こl」，看上去像长音键没了。
jaroomaji 时代方案的 preedit_format 把 l 写成 ー，换 azooKey 后这条没了。改为 L 当长音时和 - 一样算完整单位（`japaneseLIsLongVowel`）。

另外按用户 11-03 的要求，「26 键 › 长音键」三选一（带图例），默认不变：

- L 键（默认）：L 就是长音，不加键；
- L 右侧单独键：l 后面加一个 ー 键（送 `-` 进转换，`japaneseChoonpuIsCode`），L 打回字母 l（la → ぁ）；
- 代替 Shift：Shift 键点按是 ー，按住满 300 ms 才是 Shift（打字母出片假名），按住没打别的键松手照 Shift 点按切换；L 打回字母 l。

后两种由引擎选项 `_cyime_l_letter` 告诉翻译器 l 不再当 ー（`ImeSessionController.applyCandidateOptions` 每键前写），显示和退格读同一个值。
m、l 键角标不变（角标是直接上屏）。
测试：`JapaneseRomajiPreeditTest`、`JapaneseChoonpuKeyTest`、`JapaneseChoonpuKeyRenderTest`（设 `CYIME_RENDER_OUT` 出三种放法的手机、平板图和设置页图例）。未真机验收。

## 2026-11-05 读音里的光标（拖光标没反应、句中插字跑到句末）

用户反馈（日语 26 键，输入框里显示读音）：长按空格、底部留白滑动移光标对没上屏的读音不生效；把光标点到读音中间再打字，字出现在句末。

原因：这两条路只接了拼音编辑（`editablePinyin`），日语读音没接，拖动的格子被丢掉；读音中间按字母时转换状态直接收起，字母接到编码末尾。

现在：
- 长按空格、底部留白滑动（左右）按假名移读音里的光标，和翻页键盘左右键同一套（`JapaneseInputController.moveCaret`）；空格上下滑到读音两头。没在打字时照旧移输入框光标。
- 输入框里点读音中间：光标挪到那个假名后面（`placeCaret`，已经转成汉字时不动）。
- 光标在读音中间打字母、长音：插在光标处，光标跟在新字后面，候选只给光标前那段。没拼成假名的字母先留在光标处显示（さぶら|いやー 打 k 不会和 い 连成 き），拼成了才写进编码；光标前的单个 n、促音辅音写成 nn、xtsu，不会和插进去的字连读（`insertJapaneseRomaji`）。插字时假名边界按退格单位推算，不再逐字问引擎。
- 光标能挪到读音最前面（在开头插字）；在最前面时退格不动，空格、変換按整段。
- 输入框模式下光标竖线不写进输入框，输入框光标放在读音里对应位置。

纯字符串部分的测试：`JapaneseCaretInsertTest`。电脑上 azooKey 核对过插字后的读音（さぶらかいやー、かんあか、かっいか、さぶらんあいやー）。未真机验收。
