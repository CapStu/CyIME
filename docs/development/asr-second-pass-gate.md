# 语音二次校正把关（2026-11-05）

## 问题

中文「流式 + SenseVoice 二次校正」（以及整句定稿的 X-ASR）以前是第二遍出什么就整句换掉第一遍，没有任何检查，
第一遍对的词会被第二遍改成不通的同音字（如 浅绿→嵌绿、源码→圆满、厉害→力还）。

## 做法（`speech/SecondPassGate.kt`）

- 第一遍（流式预览）和第二遍按字母数字对齐，逐处找第二遍改了哪些字。
- 同样字数、只改汉字的地方：取第二遍左右各 4 个字作上下文，用九键词组模型 `rime/t9_ngram.lm`（词三元，最好分词，
  `speech/WordNgram.kt` 只读内存映射）给两种写法打分。第二遍多出模型没见过的词，或分数比第一遍低，这一处换回第一遍的字。
- 数字、英文（SenseVoice 的数字转写）、增字漏字照旧用第二遍；第二遍的标点和断句不动。
- 每次停顿定稿和说完后的整段重识别都过一遍（整段重识别和全部流式预览比）。
- 只对中文、有流式预览的组合生效；没装九键词组模型时与以前相同。没有开关。

## 测评

724 句 B 站真实评论（`B站评论-标注.csv`，去掉繁体），kokoro 中文 55 个音色合成，干净 / 20 / 10 / 5 dB 噪声（三人串音 + 粉红噪声）；
解码同应用：Paraformer 流式 100 ms 一块，SenseVoice zh + ITN，X-ASR greedy；九键词组模型精简版 v4-ls-p5e-8-c3。
合成语音不等于真人，人工标注真人集由 PC 另跑（`/mnt/project-files/asr-second-pass-1105/lab/RUN.md`）。

「误改处」= 第二遍改了且改后比第一遍更错的地方；「改对处」= 第二遍改对的地方。

| 第二遍 | 字错率 改前→改后 | 误改处 改前→改后 | 改对处 保留 | 有误改的句子 |
|---|---|---|---|---|
| SenseVoice | 7.56% → 7.11% | 171 → 58 | 776 中 721 | 20.3% → 7.7% |
| X-ASR | 6.32% → 5.89% | 141 → 48 | 863 中 814 | 16.9% → 5.7% |

余量取 0（第二遍不得比第一遍低分）：余量放到 2~4 字错率再低 0.1，但误改留下 79~86 处；余量 0 不管增删字时误改只剩 48，
但改对的丢掉 109 处、字错率只到 7.5%。分数比较只在同字数的写法之间，增删字信第二遍。

逐噪声档（SenseVoice，误改处 改前→改后）：干净 47→15，20 dB 42→13，10 dB 40→14，5 dB 42→16；每档字错率都下降。

速度：JVM 上每次合并平均 0.15 ms（724 句），最长 24 ms（首次 JIT）；只在停顿定稿和结束时各算一次，不在打字路径上。
内存：模型文件内存映射，只读到用到的页；进程不另建词表。

Kotlin 实现和测评脚本 `gate.py` 逐句结果一致（200/200）。
